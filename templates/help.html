📖 Help & Documentation

Everything you need to know about SwytchAI

🚀 Quick Start Guide

▼

1. Add Your First Device

Go to Devices → click + Add Device. Enter your switch's hostname, IP address, vendor type, and credentials. SwytchAI supports Cisco IOS, IOS-XR, Juniper JunOS, and Arista EOS.

2. Pull Your First Config

From the Devices page, click Pull Config on any device. SwytchAI connects to the switch using NAPALM, pulls the running config, and saves it with a timestamp for version tracking.

3. Check Device Health

Click Health on any device to see real-time status — port counts, up/down interfaces, error counters, and model information. The dashboard also shows a live health panel for all devices.

4. Invite Your Team

Go to Admin → add team members with appropriate roles. Admins have full access, Engineers can manage devices and configs, and Viewers have read-only access.

🔌 Managing Devices

▼

Adding a Device

Navigate to Devices → + Add Device. You'll need the hostname, IP address or FQDN, vendor type, SSH username, and password. The device must be reachable via SSH (port 22) from SwytchAI's server.

Supported Vendors

SwytchAI supports multiple vendors through NAPALM:

  • Cisco IOS — Catalyst switches, ISR routers
  • Cisco IOS-XR — ASR, NCS series
  • Juniper JunOS — EX, QFX, MX series
  • Arista EOS — 7000 series switches

Device Health Monitoring

Click Health on any device to see real-time port status, interface speeds, error counters (RX/TX), and uptime. The dashboard shows an overview health panel that checks all devices automatically.

Removing a Device

Click Delete next to the device. You'll be asked to confirm. Only admins can delete devices. Removing a device does not delete saved configs.

📋 Config Management

▼

Pulling Configs

Click Pull Config on any device. SwytchAI connects to the device, downloads the running configuration, and saves it with a version number and timestamp. Each pull creates a new version for tracking.

Comparing Configs (Diff)

After pulling multiple configs, SwytchAI automatically compares the latest version against the previous one and shows exactly what changed — added lines, removed lines, and modified sections.

Proposing Changes

Go to Changes → Propose Change. Select a device, write the config lines you want to push, and add a description. The change goes into a pending queue for approval.

Approval Workflow

Admins and managers can approve or reject pending changes. Approved changes can then be pushed to the device. This prevents unauthorized config modifications and maintains a full audit trail.

🤖 AI Config Assistant

▼

How It Works

The AI Assistant generates network configurations from natural language descriptions. Instead of writing CLI commands manually, describe what you need in plain English.

Example Commands

  • "Create VLAN 200 named Engineering on switch core-01"
  • "Configure interface GigabitEthernet0/1 with IP [IP_ADDRESS]"
  • "Set up OSPF area 0 on all Layer 3 interfaces"
  • "Create an access list to block traffic from 192.168.1.0/24"
  • "Configure NTP server 10.0.0.1 with authentication"

Best Practices

Always review generated configs before pushing them to production. The AI provides a starting point — verify the output matches your network requirements and naming conventions.

🔧 Troubleshooting

▼

"Authentication failed" when connecting to a device

Check that the username and password are correct. Make sure SSH is enabled on the device and that the user account has privilege level 15 (Cisco) or equivalent access.

"Connection timed out"

Verify the device IP/hostname is correct and reachable. Check that port 22 (SSH) is open on the device's firewall. If the device is behind a VPN, ensure SwytchAI's server has access.

"Access denied" on a page

Your role doesn't have permission for that action. Ask your admin to upgrade your role. See the Roles section above for what each role can do.

Device shows "Offline" in health check

The device may be unreachable, powered off, or SSH may be disabled. Try pinging the device from your terminal. If it responds to ping but not SSH, check the device's SSH configuration.
